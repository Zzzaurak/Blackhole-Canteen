# 吃什么？ · Stellar Bites

一只小黑洞的清华觅食日常。React + TypeScript 纯前端作业初稿，包含「星际觅食」和「吞星日志」两个页面。

## 运行

需要 Node.js 22.12+，在本目录运行：

```sh
npm ci
npm run dev
```

打开终端显示的本地网址，默认 http://127.0.0.1:5173。不要直接双击 `index.html`；本地存储区分网站的协议、主机与端口。

```sh
npm run build       # TypeScript 检查和生产构建
npm run preview     # 预览 dist（另一个端口拥有独立的本地记录）
npm test            # 时段、概率、历史评价和备份校验
npm run test:e2e    # 实际浏览器测试，需要已安装 Google Chrome
```

构建后的 `dist/` 可放到普通静态托管服务，不需要后端。所有图片保存在本项目，字体使用系统字体；运行不依赖外部字体或地图 API。

## 完成情况

- 九个食堂与恒星设定：紫荆、桃李、清芬、听涛、观畴、荷园、澜园、玉树、芝兰。
- 一至六教、紫荆学生公寓、南区本科生公寓、李文正图书馆、新物理楼及食堂参考位置。
- 独立于校园地理的局部俯视星海、向后流动的多层恒星、饭点旋臂光晕和饭后吞星反馈。
- IP 原图（透明背景）与修改背景后的星系关键帧，均由内置 imagegen 生成并保存。
- 按供餐时间、距离、个人印象、心情、偏好、最近用餐和评分进行加权抽取。
- 推荐与实际用餐分别保存，支持重抽、选定目的地、补记、编辑、逐条删除、筛选及全部推荐历史；数据管理可清空所有记录。删除推荐会保留实际用餐并解除关联。
- localStorage 持久化、JSON 导入导出、无候选状态、保存失败提示、减少动态效果和移动端布局。
- 已接入腾讯云混元生成的首版 5 秒转场，以及本地制作的反向返回片段。暂停、减少动态效果、加载失败均可直接显示结果。

**已使用腾讯云 TokenHub 生成一条视频。网页仅播放本地素材，不调用模型。**

## 当前视觉

首页按手绘参考改为星系内部的局部俯视镜头：小吞留在画面中央，星云与远处恒星共用局部镜头，向左下方缓慢流动，形成向前漂泊的感觉。食堂名默认隐藏，悬停、键盘聚焦或选中时出现。

用六条对数旋臂构建底层星海，只显示其中一小块俯视区域。恒星与气体共享旋臂坐标和镜头，气体向外围柔和散开，保留粉紫、青蓝色；恒星沿用食堂星体配色，避免过曝成白线。有食堂在参考供餐时段内时，周围云气和星场较亮；没有候选时缓慢变淡，以表现臂间环境。状态变化仅调节明暗，不再使用边界扫入特效。12:00 与 15:00 可直接对比；桃李开放的夜宵时段也算旋臂内。默认每 15 秒跟随当前时间，手动选时后固定预览，点“现在”恢复实时。暂停不会重置星体位置，暂停期间也可以预览其他时间。

点击“吃什么？”先保存推荐，再播放首版俯视转近星视频；恒星在原位淡出后，在小吞身边淡入，不再沿路径飞来；视频结束后用 700ms 叠化过渡回实时近星画面并显示结果。未选定目的地时收起结果，播放本地倒放片段，再让恒星淡回原位；点击“就去这里”后留在实时近星画面，收起时恒星直接淡出、在原位淡入，不再倒放或飞回。可随时跳过；暂停、系统减少动态效果或播放失败时不阻塞推荐。当前所有食堂共用一段金色恒星镜头，恒星类型尚未逐个匹配；实际推荐以结果卡片为准。

转场已作为独立覆盖层接入，待机仍使用 Canvas 星海。详见 [素材与后续转场](docs/media-prompts.md)。

## 使用和数据说明

- 默认按当前设备时间，早餐 06:30—09:00、午餐 11:00—13:00、晚餐 17:00—19:00；桃李延长到 23:00，玉树延长到 22:00。关闭时刻不再进入候选。
- 非饭点可手动改成 07:30、12:00、18:00；22:30 可稳定演示只抽到桃李。时段是作业参考值，不是实时营业查询。
- 口味与价格来自使用者主观评价，听涛和芝兰未知价格保留为空。
- 清青快餐、麦当劳、必胜客作为伴星展示，暂不独立抽取。未编造门店具体营业时间。
- 原始数据保存在 `stellar-bites:v1`。清空浏览器网站数据会丢失记录；请定期导出。导入前会预览记录数量并提示替换。
- 读取损坏数据时暂停覆盖，可先导出原始内容再恢复有效备份；写入失败时不把操作显示为已成功。
- 星图位置纯属构图；校园坐标仅用于远近评分，不显示伪精确的步行米数和时间。

## 作业提交检查

最新使用流程见 [当前界面操作录屏](demo-current.mp4)（27.08 秒，约 2.04MB）：设置时间与偏好 → 完整转场 → 选定食堂 → 评分和记录 → 日志 → 刷新后记录仍保留。它是真实浏览器录屏，使用隔离浏览器的示例数据，不改变你的记录。

在 `hw/hw1` 目录运行：

```sh
python3 scripts/package-homework.py
```

生成的 **`hw1-final.zip`** 就是作业附件，内含完整源码、锁文件、图片、网页视频、最新操作录屏和说明。打包不需要先启动网站，也不需要安装前端依赖；运行脚本需要 Python 3。脚本排除 `node_modules/`、`dist/`、测试截图、Git 历史及本地环境配置，并检查压缩包小于 100MB。解压后按本文开头的 `npm ci` / `npm run dev` 运行。

若之后修改了界面，需要重新录制演示：先在一个终端运行 `npm run dev`，再在本目录另一个终端运行 `node scripts/record-demo.mjs`。录制需 Google Chrome、系统 `ffmpeg` / `ffprobe` 和 Playwright 录制组件（首次运行 `npx playwright install ffmpeg`）。新录屏会覆盖 `demo-current.mp4`，完成后再执行打包命令。

作业要求源代码和不超过 30 秒的使用流程录屏合计低于 100MB；压缩包已收集这些文件。录屏位于项目根目录，ZIP 不纳入 Git。临时截图和接触表放在被忽略的 `test-results/` 中；旧测试图片和旧录屏已从当前版本清理，可从 Git 历史恢复。
